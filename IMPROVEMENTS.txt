PART A: SMALL CHANGES
---------------------

Speed
[ ] 1. Load KaTeX only when it's needed
       index.html:25 and :169 load the maths library (~270 KB) every time the app opens.
       Load it with the first formula instead. ~5 lines. Faster start-up.

[ ] 2. Add `defer` to the <script> tags
       index.html:170-187 has 18 scripts that hold up drawing the page. Make sure the
       order still holds and that main.js still runs last.

[ ] 3. Load vendor files straight from the cache (laptop browser)
       sw.js checks the network for every file and waits up to 4 s each time. The vendor/
       files (pdf.js, KaTeX, Office viewers) never change, so serve them straight from the cache.

[ ] 4. Update the service-worker cache version automatically
       sw.js:5 has CACHE = 'studyhub-v23', which is changed by hand. If it's forgotten, the
       browser keeps showing old files. Let build-android.sh / run.sh set it from the file timestamps.

[ ] 5. Resume interrupted downloads (HTTP Range)
       serve.py:259 always sends a file from the beginning. If the hotspot drops halfway
       through the 52 MB STAT notes, the download starts again from zero. About 15 lines in
       serve.py plus a few in sync.js.

[ ] 6. Compress sync replies (gzip)
       db.json (62 KB and growing) goes over the hotspot uncompressed on every sync.

[ ] 7. Redraw less every minute
       app.js:988 rebuilds the whole screen once a minute. Update only the clock and countdown text.

Reliability
[ ] 8. Force the hub file onto the disk before swapping it in
       serve.py:71 _save() writes a temp file and swaps it in, but never forces the data
       onto the disk first. Add f.flush() + os.fsync() so a power cut can't leave an empty db.json.

[ ] 9. Warn when the laptop server is out of date
       The server notes its own code's timestamp when it starts. If the .py files change
       later, the Sync panel says "Laptop server is out of date, restart it".

[ ] 10. Warn when the phone is low on space
       Low storage is what wiped the data before. Warn when the phone has under ~3 GB free.

[ ] 11. Retry a failed first sync automatically
       One timeout over the hotspot happens now and then. Retry once after ~2 s before showing an error.

Features
[x] 12. Show when the nightly cards last ran   (done 2026-11-06; APK built, not yet on the phone)
       Flashcards tab: "Nightly cards: last ran Thu 03:12 · 24 cards", or "never ran:
       check Battery → Unrestricted". Shows if Samsung is blocking the job.

[ ] 13. Offer app updates over Wi-Fi
       The phone compares its version with dist/StudyHub.apk on the laptop and shows
       "Update available: tap to install". No more USB installs or typing in the IP address.

[ ] 14. Keep the Groq model name in one place
       It's written separately in askai.py:52 and www/askai.js. Groq changes its models often,
       so one config entry means one edit.

[~] 24. Share nearby with friends   (built 2026-11-07; APK built, not yet tried on two phones)
       ☰ → Share nearby: the phone serves chosen files / decks / whole units over Wi-Fi or its
       hotspot (QR + 4-digit PIN). ☰ → Receive from a friend: scan, tick, download. Browser page
       for friends without the app. See README "Share nearby".

Project upkeep
[ ] 15. Commit after each feature
       Git has everything in one "Initial commit". One commit per item on this list
       makes it easy to undo a single change.

[ ] 16. Add two small tests
       SyncHub.merge (sync conflicts and deletions) and the formula/formatting renderer.
       Those two areas have broken the most so far.


PART B: MAJOR UPDATE (new look and behaviour)
---------------------------------------------
Bigger work, done in stages. Agree on a design first (mock-ups), then build it piece by piece.
What's there now: a slide-in drawer (index.html:97), themes light / dark / black / sepia
plus "follow the phone", quick notes that can hold todos, and Android notification
channels for ring / vibrate / silent alerts (native.js:28-34).
